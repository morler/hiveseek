# Whale 自构建与自改进任务列表

> 依据：`docs/self-evolution-plan.md`（计划基线 Whale `676a0a2`）。
> 用途：把计划拆成可独立提交、可独立验证的原子任务；每个任务只做一件事。
> 状态：任务清单草案，尚未实现，不是发布承诺，也不冻结命令面。
> 纪律：实现前须由维护者在本文档 M0-E 中确认命令名、参数与配置键，以确认结论为准。AGENTS.md 允许以设计文档代替 issue 记录此类决策（见 AGENTS.md 的 Commit & Pull Request Guidelines）。

## 0. 使用约定

### 0.1 粒度规则

1. 一个任务 = 一个可复核产出（一个函数、一个校验器、一张测试表、一份文档）。
2. 一个任务只改一类文件、只解决一个问题；不把"加固 + 开入口"合成一个任务。
3. 任务若需要同时改动生产代码与 `_test.go`，测试必须通过同一任务的判据体现，不另开任务。
4. 跨里程碑的批量测试矩阵（计划 §11）不单独成任务，按所属功能就地归属。
5. 任务编号一旦发布不复用；拆分的任务加字母后缀（如 `M1-09a`）。

### 0.2 任务卡字段

| 字段 | 含义 |
| --- | --- |
| ID | 稳定编号，用于 issue／PR 关联 |
| 任务 | 单一动作，动宾结构，只描述一件事 |
| 完成判据 | 可被第三方复核的客观结果 |
| 依赖 | 必须先完成的任务 ID |

### 0.3 全局纪律（适用于所有任务）

- 全部能力默认关闭；未启用时行为与 `676a0a2` 一致，无命令、无工具、无证据写入。
- 项目 `.whale/config.toml`、`.whale/config.local.toml` 只能收紧权限，不能授予自改／激活能力。
- subagent、workflow agent、ACP 连接不默认继承激活权限；`--dangerously-skip-permissions` 不能取消本功能的专用确认。
- 不复制 jcode 的共享 daemon、ambient 调度、overnight 永久在线循环或服务器多通道部署。
- 不新增模型供应商、自动训练、跨项目通用记忆库或另一套 workflow 调度器。
- 不把"编译成功""版本字符串匹配""模型自评分"作为质量提升证明。
- 状态只能由控制器依据可核实事实推进；不接受模型输入 `verified=true` / `ready=true`。
- 报告"需人工审查"不等于通过。
- 任何失败路径 fail closed，不退化为宿主自动执行或裸替换。
- 不提交 `~/.whale/` 数据、`.whale/settings.json`、会话日志、API key 或生成二进制。

### 0.4 里程碑总览

### 0.5 全局开放顺序（硬约束）

```text
M0 全部
  → M1 后端加固 → M1 装配与入口 → M1 测试与文档
  → M2 身份与来源 → M2 验证器 → M2 报告与 CLI
  → M3 监督者 → M3 安全点 → M3 ready 与回滚 → M3 测试与演练 → 开放 activate
  → M4（另行批准，仅依赖 M1 与 M2 完成）
```

- 后端加固与隐私先于入口开放：M1-01～M1-34 未完成前不得实现 M1-47 及之后的命令。
- 验证器先于激活：M2 未产出可复核报告前，M3 不得开始。
- 监督者先于 ready 切换：M3-01～M3-12 未完成前不得实现 M3-28 指针切换。
- 没有 M3 时停止于候选，不得临时用 `syscall.Exec` 顶替监督者。

## 8. 明确不在任务清单内的事

以下条目来自计划 §1.3 与 §4.3，任何任务都不得顺带实现：

- 共享 daemon、ambient 调度、overnight 永久在线循环、服务器多通道部署。
- 新增模型供应商、自动训练模型、跨项目通用记忆库、另一套 workflow 调度器。
- 自动修改用户项目、全局配置、权限策略、hooks、API key 或会话存储格式。
- 替换 npm／包管理器拥有的可执行文件；在 Windows 上原地自动换版或透明重连 ACP。
- 自动创建新技能、批量改写技能、全局技能发布或通用 memory 写接口。
- 把 project memory 纳入本轮改进。
- 一键跳过测试或确认的激活通道。
- agent 自行修改基线资格记录。
- 为执行边界 wrapper 增加更新职责。

## 9. 未决问题对任务的影响

计划 §14 的五项未决问题不阻塞本清单，但决定哪些任务可开工：

| 未决问题 | 建议默认答案 | 未确认时的处理 |
| --- | --- | --- |
| 首版是否包含技能全局写入／新建 | 不包含，只改项目中已有技能 | M1 保持只读或退回普通文件编辑流程 |
| 开发安装怎样与 npm 版本共存 | 用户主动配置独立 managed 启动入口 | 只交付 L2，M3 全部任务挂起 |
| 自主验证用哪种沙箱 | 选宿主已可用的隔离运行时 | M4 只生成 diff，M4-17 及之后挂起 |
| 何时批准受保护变更与更新 baseline | 分开人工审阅 diff 与新基线，批准绑定具体 hash | 标记 `needs_review`，拒绝激活 |
| 是否需要 ACP 运行中重连或常驻自改 | 不在首版，另开设计评估 | M3-54, M3-55 保持明确拒绝 |

实际命令面须先由维护者在本文档 M0-E 中确认（M0-20），不把草案直接当冻结接口。
